## What is Token Listing?

In the age of agents, design tokens are increasingly necessary to ensure consistency and maintainability in code environments. The W3C [Design Tokens Community Group (DTCG)](https://www.designtokens.org/) has built a standard that supports design and token authoring tools, but it does not fully address the needs of tools that consume built design tokens in code.

In code environments, design tokens take many shapes, depending on styling system, framework or platform, or even team conventions. Because of that, tools for design tokens in code either have to enforce strict conventions on token structure, or implement complex parsing and customisation logic. This situation has hindered innovation on token tools for developers.

The Token Listing format solves that problem. It's produced by token translation tools like Style Dictionary and Terrazzo, and maps DTCG tokens to their exact representations in code. It provides a predictable, machine-readable structure for tools to manipulate tokens in code environments regardless of how they're actually implemented.

## Who is it for?

<CardGrid>
  <Card title="MCP servers" icon="laptop">
    Expose structured token data to AI assistants and agent-based tooling.
  </Card>
  <Card title="Code generation tools" icon="right-arrow">
    Translate token names accurately during code generation or translation.
  </Card>
  <Card title="Documentation sites" icon="open-book">
    Render token previews, names, and descriptions regardless of how complex your tokens are.
  </Card>
  <Card title="Diff &amp; changelog generators" icon="magnifier">
    Track which tokens changed, were added, removed or deprecated between releases.
  </Card>
  <Card title="Search indexes" icon="magnifier">
    Power "find this token" features in IDEs and design tool plugins.
  </Card>
  <Card title="Linting tools" icon="warning">
    Enforce token pairing policies based on their subtypes, prevent deprecated token usage, etc.
  </Card>
</CardGrid>
