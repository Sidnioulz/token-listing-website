## What is Token Listing?

In the age of agents, design tokens are increasingly necessary to ensure consistency and maintainability in code environments. The W3C [Design Tokens Community Group (DTCG)](https://www.designtokens.org/) has built a standard that supports design and token authoring tools, but it does not fully address the needs of tools that consume built design tokens in code.

In code environments, design tokens are rarely represented in the DTCG format. Every styling system, framework or platform has its own conventions for naming and structuring tokens. Organisations often handroll token translation logic to meet their own team conventions and requirements.

Because of that, building interoperable tools for design tokens in code seems impossible. Documentation sites, search engines, diff algorithms, changelog generators, linters, skills, MCP servers, design audit tools all could benefit from a standardized representation of design tokens in code environments.

The Token Listing format fills that gap: it's produced by token translation tools like Style Dictionary and Terrazzo, and maps DTCG tokens to their exact representations in code. It provides a predictable, machine-readable structure for tools to manipulate tokens in code environments regardless of how they're actually implemented.

## Who is it for?

<CardGrid>
  <Card title="MCP servers" icon="adjusted/tabler-robot">
    Expose structured token data to AI assistants and agent-based tooling.
  </Card>
  <Card title="Code generation tools" icon="ph:magic-wand">
    Translate token names accurately during code generation or translation.
  </Card>
  <Card title="Documentation sites" icon="ph:books">
    Render token previews, names, and descriptions regardless of how complex your tokens are.
  </Card>
  <Card title="Diff &amp; changelog generators" icon="adjusted/lucide-diff">
    Track which tokens changed, were added, removed or deprecated between releases.
  </Card>
  <Card title="Search indexes" icon="adjusted/tabler-database-search">
    Power "find this token" features in IDEs and design tool plugins.
  </Card>
  <Card title="Linting tools" icon="ph:shield-check">
    Enforce token pairing policies based on their subtypes, prevent deprecated token usage, etc.
  </Card>
</CardGrid>
